# Regatta

The game is called Regatta. The repo folder and package scope still say slack-tide, the earlier working title.

Browser sailing simulator. The plan is `docs/PRD.md`. Read it before starting a milestone.

## Standing rules from the PRD

- Build milestone by milestone. Stop at each gate for a play test. Do not start the next milestone until the user says the gate passed
- `packages/sim` has no rendering or browser code, ever. It must stay deterministic: fixed step, no `Math.random`, no clocks
- Never add an on-screen button for a sailing action. If a control seems to need one, raise it as a question
- Before changing physics, make sure the golden-track test exists and passes. After an intended change, run `npm run golden:update` and look at the diff
- Adding a boat or a course should add data, not code

## Commands

- `npm test` runs the sim, world and nav tests. `npm run typecheck` checks all packages. `npm run dev` serves the client
- `npx vite-node scripts/tune.ts` prints reef crossovers, speeds against the polar and the tacking angle

## Conventions that are easy to get wrong

- Sim: x east, y north, metres. Heading is compass radians, clockwise from north. Speeds in m/s, `KT` converts
- Every signed sim value is positive to starboard: rudder (turns the boat to starboard), heel (leans to starboard), boom and jib clew angle, leeway speed, and wind angles (wind on the starboard side)
- Client world: X east, Y up, Z south, so sim (x, y) maps to (x, 0, -y)
- Boat model frame: +X starboard, +Y up, -Z forward, origin on the waterline amidships. The boat's rotation is YXZ with y = -heading, x = pitch, z = -heel
- Jib sheets are stored as slack in radians, 0 is hard in. Mainsheet is the widest boom angle it allows
- Interactive parts are named nodes (`wheel`, `boom`, `winch_port`, `winch_stbd`, `furler`). Bindings live in the boat's JSON `controls` list

- The world is `ReplayWorld` in `packages/world`, fed by `courses/sf-bay` (baked by `pipeline/`, see its README). Session time is seconds since the session start. `startOffset` places it in the season
- Course coordinates are flat metres east and north of `course.origin`. Grids have row 0 at the southern edge
- Chart and planning live in `apps/client/src/ui/chart.ts` and `passage.ts`. The maths is in `packages/nav` and is tested there

- The autopilot's steering is in the sim (`helmMode` heading, wind or route, `setRoute`). The player-facing part is `apps/client/src/input/pilot.ts`. Pilot on means crew trimming on
- Shared water is `apps/client/src/net/fleet.ts`, built on a `room` with presence (the artifact runtime's on claude.ai, Supabase's on the website). It needs `capabilities: { room: {}, user: { scopes: ["profile"] } }` when publishing. Clocks agree two ways: a boat that has just arrived takes up the clock of the boats already out (she sends `nw: 1` for her first seconds and nobody follows her then), and after that everyone moves up to the furthest-on boat with `world.shiftTime`
- Traffic positions are pure functions of session time, so every player sees the same vessels
- Wind is NOAA HRRR, stream and tide NOAA SFBOFS. The season runs 36 hours from 08:00 PDT on 14 July 2024. Start times offered on the join screen are in `courses/sf-bay/times.json`

- Entry is `main.ts` (boot and frame loop), `stage.ts` (scene everyone shares), `lobby.ts` plus `ui/join.ts` (the join screen), `session.ts` (one sail). `window.regatta` holds debug handles once a sail starts
- Boat display fields and the picker order live in `boats/*.json` and `boats/lineup.json`. `BoatView` takes a livery (topsides colour, transom name)

- The board (key B) is `ui/board.ts`: roadmap with votes, release notes, feedback form, logbook. The roadmap is `src/data/roadmap.json`, release notes `src/data/releases.json` (newest first). Every publish adds a note there: the newest note's id is what marks the "New" flag for returning players
- Votes, feedback and logbooks are in the artifact's `db` (`net/store.ts`, `net/logbook.ts`): `votes/<uid>`, `feedback/<uid>`, `profiles/<uid>`. Feedback is readable only by its sender and by editors. Writing needs Contributor access to the page
- Publishing needs `capabilities` with `room`, `user` (profile scope) and `db` with the six rules (votes, feedback, profiles, each with a `{self}` rule). Omitting `capabilities` on a republish carries them forward
- Feedback is copied to the Google Sheet "Regatta feedback" in the owner's Drive by hand for now (read `feedback` with ArtifactData, append rows). The page cannot post to Google itself
- Coaching hints are `ui/hints.ts`, gust look-ahead is `ui/gusts.ts`. Both only read the sim and the world
- A saved boat is only restored if `isSoundState` passes. `Sim.restore` fills fields a saved state lacks from a fresh state, so adding a field to `SimState` cannot break a boat handed across a republish
- Racing is `apps/client/src/race/` (`race.ts` the rules and the room protocol, `pace.ts` the autopilot pace boats) with the panel in `ui/fleetpanel.ts` (key R). Courses are data in `courses/sf-bay/races.json`: the first mark is the start. A race is announced through room presence (`rc` the call, `rj` joined, `rp` marks rounded, `rd` metres to go, `rf` finish time). Everything read from another boat's presence goes through `readCall` first
- A race can be fixed for a real time: an entry in `apps/client/src/data/events.json` (course id, start spot, ISO time). `race/events.ts` reads it. Every boat builds the same call from it, its countdown runs on the real clock (`RaceCall.at`), it shows on the join screen and under the clock, and it opens for joining 25 minutes before the gun
- Things to do aboard besides sailing are plug-ins: a class in `apps/client/src/aboard/` implementing `Feature` (`feature.ts`), listed in `aboard/index.ts`. The session calls the hooks (key, step, update, status, focus, wire). Anchoring and mooring are in the sim: `holdAt`, `release`, `state.hold`
- Anchoring, moorings, docks and the night aboard are `aboard/mooring.ts` (keys X and Z) with the pure decisions in `mooringRules.ts`. Crab pots (`pots.ts`, key K) and fishing (`fishing.ts`, key L) share the pure catch logic in `catch.ts`, which uses hashes, never `Math.random`, so tests can pin it. Client tests live in `apps/client/test/`
- The tender is a kayak: `aboard/kayak.ts` (key O) with pure paddling and landing rules in `paddle.ts` and the model in `kayakModel.ts`. She is stepped on real seconds in `update`, and she stops at the drawn shoreline (read from the scene's terrain mesh), not at the depth grid's. Her position goes out in presence as `oc`; nothing draws other players' kayaks yet
- `aboard/dock.ts` steps the crew straight ashore with O when she is alongside a dock; `aboard/visited.ts` remembers which places have been landed at (localStorage `regatta.ashore`) for the bar-hop card on the Logbook tab. `aboard/cheat.ts` is the strip of main keys shown for the first minute of a sail (key /)
- The city is `scene/city.ts` (landmarks from a `SITES` table of latitude and longitude, the waterfront, Alcatraz, the Bay Bridge) built through `scene/massing.ts` into one merged mesh with windows drawn by the material and lit after dark. It hangs off the Bay's `san-francisco` scenery piece. Piers are only placed where the depth chart is shoal, so nothing blocks sailable water
- `aboard/guide.ts` (key G) draws the race marks as buoys, a beacon and range label on the next one, and a line of arrowheads on the water; on by itself in a race. `aboard/wildlife.ts` draws the animals, whose rules are the pure `fauna.ts` (keyed by course id, hashed off season time so every player sees the same); `sightings.ts` keeps the per-device list
- `aboard/tow.ts` (key U) moves a boat that is aground to the nearest deep water
- Order in `aboard/index.ts` matters: the first feature to answer gives the status and the first to take a key keeps it
- A boat's held state is drawn by `BoatView` from `state.hold` (sails stowed, boom cover, rode or mooring line), so other players' boats and the pace boats show it too. It travels in presence as `hd`, `hx`, `hy`
- The platform seam is `apps/client/src/net/platform.ts`: the only place that asks for `room`, `db` and `user`. On claude.ai it returns the artifact capabilities. On the website (bajaregatta.com, Vercel) it loads `net/web/`, the Supabase backend: one public Realtime channel per water for shared water and races (Broadcast, send rate set by the adapter to stay inside the plan's message limits), tables `votes`, `feedback`, `profiles` with row-level security (SQL in `supabase/migrations/`), sign-in by emailed link. The single-file Artifact build leaves all of it out (`VITE_BACKEND` in `vite.config.ts`)
- Waters are folders under `courses/` (`sf-bay`, `san-juans`), found by glob in `world/loadCourse.ts`; each has `about.json` (name, scenery pieces) plus course, starts, times, places, races and optional traffic. The pipeline bakes one with `pipeline/bake.py <id>` from a definition in `pipeline/courses/`. Each boat sends her water as `cs` and the fleet ignores boats on another. The single-file build loads every course up front (`__SINGLE__`): load-on-demand modules inlined into one script break its start-up
- Joining a race tows a far-off boat to a berth in the start area (`Race.musterAtStart`)
- Vercel builds from `apps/client` using `apps/client/vercel.json`, which installs from the workspace root. Production deploys from `main`
- The wind tunnel view (key F) is `aboard/flow.ts`. Its smoke lines are drawn from the sim's trim state (luff, stall, backed), not from a fluid solver
- `scripts/legs.ts` checks marks and legs against the depth chart before a course or place goes into the data. That is not enough on its own: a straight leg can be clear and the pilot still put a boat ashore beside it. `npx vite-node scripts/sailcourse.ts <race id> [hours] [boat]` sails a course on the route pilot and must finish for every boat before a course ships. `scripts/depthmap.ts` prints the depth grid for an area
- The recorded weather is 36 hours. `world.wrapSeason` moves a session back a day when it reaches the end. Boats whose clock is past the end are not followed

## Expedition

A second way to play, asked for on the first screen (`ui/mode.ts`). It lives on the `pirates` branch (cut from `expedition`) and is unpublished. There are two things to do in it, offered as cards on the briefing (`cards.ts`, an `Offer` each). The first and main one is the pirate game, "On the Account, 1715" (`expedition/pirates/`): the owner asked for it in place of more Shackleton, as "plunder and gain riches and artifacts and sail freely in battles in the Caribbean". Its stage 1 is built: see the pirate section below. The second card is Shackleton's boat journey in the James Caird, 1916, whose stage 1, "She floats", is done and whose stages 2 (the six men) and 3 (navigation) are not started and are not the priority.

- Everything is in `apps/client/src/expedition/`. `start.ts` is the way in and out (`Expedition`): `main.ts` makes one when Expedition is chosen and gives it the frame. It builds the sea, hands the stage over, and `leave` puts the stage back for Regatta. `?mode=expedition` answers the first question and opens the pirate game, `&voyage=caird` the boat journey instead, `&go=1` casts off at once, `&seed=7` pins the weather and the traffic, `&truth=1` draws the Caird's true track on the chart, `&fresh=1` forgets the saved pirate career. `?go=1` alone still means Regatta
- A voyage is data: `voyage.ts` is the shape, `voyages/caird.ts` the first. It holds the briefing, the coasts as latitude and longitude, the day-by-day weather script with what the record says for each day and how far to trust it, and `events` (the recorded happenings, which nothing reads yet: they are for stage 2)
- The sea is made, not baked: `sea.ts` (`buildSea(voyage, seed, options)`) returns the same package a baked course is (`LoadedCourse`) so `ReplayWorld` and the stage take it unchanged, plus `projection`, `land`, `weather` and `sky()`. `weather.ts` turns the script and a seed into wind, cloud and air temperature. `land.ts` is the coast geometry and the height of the ground. Same voyage and seed, same sea, byte for byte. It is not in `courses/`, so the Regatta water picker never lists it
- The chart is Mercator about 57.8 S (`packages/nav/src/chartwork.ts`, with rhumb lines, dead reckoning and the Beaufort scale). North is up and bearings are true everywhere, but a flat metre is not a true metre away from the middle latitude: 10% long at Elephant Island, 9% short at South Georgia. The sim sails in flat metres. The log converts to true miles with `projection.scaleAt`
- The boat is `boats/caird.json` (not in `lineup.json`, so not in the picker) drawn by `boat/buildCaird.ts` and `boat/cairdView.ts`. `BoatDrawing` in `boatView.ts` is what the input layer needs of any boat's drawing: `BoatView` and `CairdView` both answer to it. Her control nodes are `tiller`, `main_sheet`, `jib_sheet_port`, `jib_sheet_stbd`. The sim has one main and one jib: the lug main is the main, the mizzen is drawn and follows it. The three "reefs" are sail plans (`SAIL_PLANS` in `watch.ts`): full sail, reefed down, storm canvas with the jib handed. Her polar is for full sail and the reefs' `drive` is set low, so that shortened down in a gale she makes about three knots
- `session.ts` (`ExpeditionSession`) is the counterpart of `Session` and shares nothing with it but the stage, the sim, the camera and `Controls`. No fleet, race, pilot, board or `aboard/` features. Keys: Enter stands a watch or calls all hands, left and right alter the course while the helmsman steers (or move the tiller when it is the player's), P passes the tiller, R shortens sail, X heaves to, M the chart, / lists them
- Two speeds of time. In real time the sim sails her. On watch (`watch.ts`) time runs about 850 times faster and `watchStep` carries her forward a minute at a time from `Performance`, a table of speed and leeway measured from the sim itself when the voyage is made (`measurePerformance`), so fast and real time agree within a few per cent. The sim still runs at the speed of the eye during a watch so she looks alive, and her position and clock are overwritten each frame, so leaving a watch is seamless. `npx vite-node scripts/caird.ts [seed]` prints the table, the day-by-day wind and the agreement
- Hove to is the sim's `hold` with an anchor point that drifts down wind (the sea anchor): she lies head to it and goes to leeward at a knot. The crew heave to by themselves at 48 knots and make sail again at 40
- What ends a watch is the list in `wake.ts` (`WAKE_CHECKS`): a gale, a storm, land in sight, going aground. Stage 2 adds its own there. Arrival and being lost are in `ExpeditionSession.lookOut`
- The reckoning (`ExpeditionSession.reckoning`) is carried on from the heading steered and `judgedSpeed`, a speed called to the half knot. It leaves out leeway and the stream, which is why it drifts. The true track is kept in `truthTrack` and never shown without `?truth=1`. With no sights yet, the reckoning is typically 150 to 250 miles out at the landfall, nearly all of it the stream. Stage 3 builds on both tracks
- The scene is drawn near its own zero: `stage.origin` says where that is in course metres, because the water shader's precision runs out a few tens of kilometres from zero. `ExpeditionSession.scene` is the boat in scene metres. In a watch the origin slides under her every frame. Anything added to the scene on an expedition must be placed relative to `stage.origin` (see `ice.ts`)
- Seams left in shared code, all of which Regatta leaves at their defaults: `stage.sea` (a `SeaModel`: the ocean swell is `swell.ts`, with a gain for a smaller sea), `stage.origin`, `stage.sunPlace`, `stage.overcast`, `stage.haze`, `LoadedCourse.lands`, `sky.setOvercast` and `bakeGapMs`, `ocean.setHull`, `setWater` and `setShoals` (a map of shoal water the sea is tinted by), the `ice` and `tropic` ground covers in `terrain.ts`, `hood`, `kerchief` and `bulk` on the crew figure's kit, `Controls.dispose`. `SeaOptions` in `sea.ts` (weather, shelf, reefs, ground height, grid sizes) and `WatchRig` in `watch.ts` are how a second sea and a second boat differ from the Scotia Sea and the Caird: both default to those
- The instruments are `instruments.ts` (`PeriodHud`): compass, speed by eye, the wind as a point and a Beaufort force in words, the date and time. The chart is `bareChart.ts`: land, graticule, the reckoned track and the bearing and distance of the landfall from it. Neither shows anything she could not know
- Tests: `apps/client/test/expedition.test.ts` (the sea, the script, the boat's polar, watches, the wake list) and `packages/nav/test/chartwork.test.ts`
- Not handled yet: a republish mid-voyage or mid-cruise starts again from the first screen (the hot hand-over only knows Regatta sessions)

### The pirate game (`apps/client/src/expedition/pirates/`)

An original game: no names, characters, art or screen layouts from any other pirate game. History is fair material. Everything about the period, the chart and the ships is from memory and says so in the file it is in.

- Data, so that adding one adds no code: `tables.ts` holds ship classes (size, masts, guns, crew, hull, speed, courage, purse), goods, ports (prices, yard, recruits, the notoriety at which they shut), sea lanes (turns, who sails them, what they carry, the tavern's rumour) and the 22 artifacts. The player's sloop is `PLAYER_CLASS` there and `boats/jamaica-sloop.json` for the sim (not in `lineup.json`)
- The sea is `caribbean.ts` (`buildCaribbean(seed)`): Jamaica, south-east Cuba, western Hispaniola with Tortuga and La Gonâve, the Windward Passage, the Caymans, Great Inagua, about 990 by 490 km, Mercator about 19.1 N. Land and reefs are the same for every seed. The trade wind (`makeTrades`, east, 12 to 22 kt, freshest mid afternoon, sea and land breezes off high islands) and squalls (`squallAt`) are pure in place, time and seed. `TradeWorld` is a `ReplayWorld` whose wind is asked of the weather itself, so a cruise has no end. Depth is in whole metres here: a reef is patches of 1 m water in a shoal
- Pure rules, each with tests in `apps/client/test/pirates.test.ts`, hashes and never `Math.random`: `gunnery.ts` (bearing arc, hit chance from range, aspect, heel, sea and skill, raking, reload by crew; the rules are listed at its head), `boarding.ts`, `loot.ts` (prize contents, stowing, prices, port costs), `traffic.ts` (ships on lanes as functions of time and seed, and the plain speed rule other ships sail by), `sighting.ts` (tops, hull, colours, close; the spyglass line), `career.ts` (what is kept in localStorage `regatta.pirate`, read only if sound)
- `game.ts` (`PirateGame`) is the whole game with nothing drawn: the sloop's hull, rigging, men and guns, the ships near her (`LiveShip`, taken off their lanes within 42 km and given a mood: cruise, flee, fight, struck, taken, sinking), firing, boarding, prizes, forts, ports. It reports through `events`. `session.ts` (`PirateSession`) sails the sloop with the sim and draws it. `npx vite-node scripts/corsair.ts [seed] [cruise|duels|all] [n]` plays a chase, a fight, a port visit and duels against every class with no drawing: run it after touching any number in gunnery, boarding or the ship table
- Heel is the sim's: the session passes `state.heel` to the guns. Past 7 degrees the lee battery loses its chance (none by 15) and the weather battery shoots high into the rigging. Rigging shot away scales the polar on the session's own copy of the boat file (`applyRigging`) and `drive` in a watch
- Keys (the session's own, through `Controls`): Z larboard broadside, C starboard, B board or send the boat to a ship that has struck, G glass to the next sail, F the helmsman chases the ship in the glass (the clock runs on by itself until 400 m), Enter a watch, left and right the course, P helmsman or the tiller, R reef, X heave to, L go ashore, K the cabinet, M chart, / the list. Coming to rest (X) inside a port's anchorage opens the port sheet. A port sheet is business ashore, so it has buttons
- Drawing: `shipModel.ts` (`PeriodShip`) draws any class from its table row (gaff or square sails per mast, gun ports, colours by nation) and `sloopView.ts` wraps it as the player's `BoatDrawing` with the crew. Other ships are drawn larger than life far off and sunk below the curve of the sea, so masts lift first. `effects.ts` is smoke, shot, splashes and the guns' sound. `scenery.ts` is the towns (each on a spit run out toward its anchorage, because the made coast shelves too slowly to lie under houses), palms and the shoal map. `chart.ts` is the rover's chart: position shown plainly, ports, reefs, the rumoured lane, sails in sight. `ui.ts` is the sloop's panel, the glass, the port sheet, the cabinet, the boarding read-out and the end card
- Money: coin from a prize is aboard and at risk. Lying in an open port banks it. Losing the sloop (sunk, taken, wrecked) loses what is aboard, halves the bank and the notoriety, and keeps the cabinet. Notoriety shuts Santiago at 12 and Port Royal at 40 (forts fire), brings out the guarda costa and the King's sloop a little before, and fills taverns
- Seams, each marked `SEAM` in the code: square rig and a bigger player ship (`traffic.ts` `shipSpeed`, `shipModel.ts`, `rig.ts`, `career.ts` `ship.cls`), fleets (`game.ts`, `traffic.ts`), more of the Caribbean (`caribbean.ts` is one `SeaDef`; `chart.ts` draws whatever it has), treasure hunts from artifact charts (`career.ts`, `chart.ts`), other players in the same sea (`traffic.ts` is already the same for everyone with a seed; `game.ts` `LiveShip`)
- Not done: nothing is persisted mid-cruise but the career at each port and prize, so a reload starts off the last port. Other ships have no crew figures. The drawn shoreline and the depth chart's can differ by a kilometre. Night is only dark. The scripted captain in `corsair.ts` is the only thing that has played a whole cruise: no person has
